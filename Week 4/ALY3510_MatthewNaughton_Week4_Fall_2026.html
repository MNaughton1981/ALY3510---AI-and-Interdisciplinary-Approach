Teaching a Machine to See:
Learning From Data With Google's Teachable Machine

Machine learning is often explained in abstract or highly technical terms, but the basic idea is fairly intuitive. Instead of programming a system with a complete set of rules, we give it examples and allow it to identify patterns in those examples (Russell & Norvig, 2021). Google's Teachable Machine makes that process visible by allowing users to train image, audio, and pose classifiers directly in a web browser without writing code (Carney et al., 2020; Google, n.d.).

For this exercise, I trained a two-class image classifier using webcam selfies. I originally thought I was teaching the model to recognize two different concepts: facial expressions and camera perspectives. What I actually taught it was something much simpler. The model learned that forward-facing images belonged in one class and images with a turned head or a hand near the face belonged in the other. That difference between what I intended and what the model learned became the most useful part of the project. It showed that a machine-learning model responds to patterns in its training data, not to the meaning its designer has in mind.

How the Model Learned From Data

Teachable Machine is built on TensorFlow.js and runs in the browser (Carney et al., 2020). For an image project like this one, it does not train an entire neural network from the beginning. It uses transfer learning with MobileNet, a convolutional neural network that was previously trained on the ImageNet dataset to recognize common visual features such as edges, textures, and shapes (Howard et al., 2017).

The pre-trained part of the network remains frozen and works as a feature extractor. Each image is converted into a numerical representation, called an embedding, that summarizes its visual features. Teachable Machine then trains a much smaller classifier to connect those features to the labels assigned by the user. Because MobileNet has already learned how to identify useful visual patterns, Teachable Machine can produce a usable classifier from a relatively small number of examples in only a few seconds.

The training process follows the standard supervised-learning cycle. Each image is paired with a label, and the model makes a prediction about which class that image belongs to. It then compares its prediction with the correct label and measures the difference using a loss function. Through backpropagation and gradient descent, the model adjusts the weights in its classifier to reduce that error. It repeats this process over multiple passes through the training data, known as epochs (Goodfellow et al., 2016).

Teachable Machine also provides advanced settings for epochs, batch size, and learning rate. These settings are not necessary for creating a basic model, but they help show how the training process can be adjusted. The overall process moves from collecting and labeling examples to extracting visual features, training the classifier, testing the results, and making changes when the model does not behave as expected.

What I Observed

Experimental Setup

I created an Image Project with two classes of webcam selfies taken at my desk under ordinary indoor lighting. Class 1 contained 15 images and was intended to represent facial expressions. These were mostly straight-on, forward-facing pictures in which I changed my expression. Class 2 contained 20 images and was intended to represent different camera perspectives. These included profile views, upward and downward angles, and images in which I turned my head to the left or right. In several Class 2 images, I also rested a hand near my chin.

The complete dataset contained only 35 images. I trained the model using the default settings and then tested it in the live preview with poses and expressions that were not included in the original training samples.

Looking back, the most important decision was how I defined the classes. Rather than creating two parallel categories, I tried to teach the model two different ideas at the same time. Class 1 emphasized expression, while Class 2 emphasized viewpoint. This made it difficult to tell which visual characteristic the model would use to separate them.

Observations During Training and Testing

The first thing I noticed was how quickly the model trained. Despite having only 35 images, the training process finished within a few seconds and produced confident predictions in the live preview. MobileNet's pre-trained visual features were doing much of the underlying work, so the smaller classifier only had to learn how those features related to my two labels.

When I sat straight on and looked directly into the webcam, the model classified the image as Class 1 with about 90 percent confidence. The remaining confidence was assigned to Class 2. When I turned my head into a profile, looked up or down, or raised a hand toward my chin, the prediction shifted toward Class 2.

What I found most interesting was that changing my facial expression had very little effect when I continued facing forward. Changing only my head position, on the other hand, could cause the classification to flip. Once I noticed this, the model's behavior made much more sense.

I had intended Class 1 to represent expressions and Class 2 to represent camera perspectives. The model had no way to understand that intention. It only saw two groups of images and looked for the visual patterns that separated them most reliably. Nearly all the Class 1 images were forward-facing, while Class 2 contained turned heads, angled views, and several images with a hand near the face. Head orientation and hand placement therefore became much stronger dividing features than facial expression.

The model had not learned the abstract difference between an expression and a camera perspective. It had learned a simpler statistical rule: forward-facing images usually belonged to Class 1, while angled images or images containing a hand near the face usually belonged to Class 2. That rule matched the training data even though it did not match the concept I thought I was teaching.

The small dataset was another limitation. With only 15 images in one class and 20 in the other, the model had very few examples from which to learn. The classes were also slightly imbalanced. Even so, the model produced confident results. This was an important reminder that confidence does not prove that a model has learned the correct concept. A model can make a decisive prediction based on an unintended shortcut in the data.

This behavior reflects a broader problem in machine learning. Models optimize for the statistical signals that best separate the labeled examples, which are not always the features a person considers meaningful (Lake et al., 2017). A better version of my experiment would isolate one variable at a time. For example, I could keep my head position and lighting consistent while changing only my expression. If I wanted to classify camera perspectives instead, I could keep my expression consistent while changing only the angle of my head.

The flawed class design turned out to be more educational than a perfectly designed experiment might have been. It exposed the difference between my understanding of the categories and the information that was actually present in the dataset.

Machine Learning Versus Human Learning

Similarities

Even with its limitations, I noticed several similarities between how the model learned and how people learn. Both can identify patterns by seeing examples rather than receiving a complete set of rules. Both also benefit from having more examples and from seeing greater variety within those examples.

Prior knowledge also plays an important role in both cases. The Teachable Machine classifier was able to learn from only 35 images because MobileNet had already been trained to recognize general visual features. In a different but comparable way, people use years of accumulated visual experience when learning to recognize something new. Neither begins the learning process with no prior knowledge at all.

People and models can also focus on misleading shortcuts. The classifier treated head orientation as the main dividing feature because that was the easiest way to separate the training images. A child who sees only a narrow range of examples may make a similar mistake by treating an incidental feature as if it defines an entire category. Additional examples and corrections can help refine that understanding over time (Lake et al., 2017).

Differences

The similarities only go so far. Human learning is generally more flexible and efficient than the learning demonstrated by this model. A person can often recognize a new category after seeing only one or two examples, while a machine-learning model typically benefits from a larger and more varied training set.

People also use context, meaning, and causal reasoning. A human observer understands that a facial expression and the direction a person is facing are different characteristics. The model does not understand either concept. It only identifies relationships between numerical image features and the labels it received (Lake et al., 2017; Russell & Norvig, 2021).

There is also a difference in how the results can be explained. A person can usually describe why an image belongs to a category. Teachable Machine provides confidence scores, but those scores do not explain the model's reasoning or identify the exact features that controlled the prediction.

Human learning also continues across situations and combines information from multiple senses and experiences. The classifier's learning took place during a defined training session. Once training stopped, the model's parameters were fixed unless it was trained again. Retraining can introduce problems such as catastrophic forgetting, in which a system loses previously learned information while adapting to new data (Goodfellow et al., 2016).

Conclusion

Building a classifier in Teachable Machine made the mechanics of supervised machine learning easier to understand than reading about them alone. The project showed how labeled examples are converted into numerical features and how a model adjusts its parameters to reduce prediction error. It also made concepts such as transfer learning, confidence scores, training-data quality, and unintended correlations much more concrete.

The central lesson came from the weakness in my own experimental design. I intended one class to represent facial expressions and the other to represent camera perspectives. Because the two groups also differed in head orientation and hand placement, the model learned those more obvious visual patterns instead. A forward-facing image was classified as Class 1 with roughly 90 percent confidence even when I changed my expression. Turning my head caused a much larger change in the prediction.

A human observer would understand that the question "What expression is this person making?" is different from "Which direction is this person facing?" The model did not know which question I intended to ask. It simply found the feature that most consistently separated the two groups of images.

For me, the practical lesson is that the quality of a model begins with the way the problem and training data are defined. A strong algorithm cannot correct labels that represent mixed concepts or examples that contain unintended patterns. If I want a model to learn a specific distinction, I need to design the classes carefully, control unrelated variables, and test whether the model is responding to the intended feature.

As I move further into analytical decision-making, that is the part of the exercise I am most likely to carry forward. A model's confidence can make its output appear credible, but the output is only as meaningful as the data and assumptions behind it.
